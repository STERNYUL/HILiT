## 1. Google Cloud Video Intelligence — 🔴 K2 결격

### 판정 근거

**bbox 시계열은 나온다.** `includeBoundingBoxes: true`로 정규화 좌표(left·top·right·bottom)를 얻는다.

**그런데 "누구인지"가 없다.**

| 확인 항목 | 결과 |
| --- | --- |
| 지속 track ID | 🔴 응답에 **없다** — `tracks[].segment`의 시간 구간만 반환 |
| 대상 지정 입력 | 🔴 **불가** — `PersonDetectionConfig`는 `includeBoundingBoxes` · `includePoseLandmarks` · `includeAttributes` 셋뿐이며 **참조 이미지나 bbox를 입력으로 받지 않는다** |

> **REQ-FUNC-002가 요구하는 것은 *"사용자가 자기를 1회 지정하면 가려졌다 나타나도 동일 인물로 인식"* 이다.** GCVI는 **사람이 있다**를 알려줄 뿐 **그 사람이 당신이다**를 알려주지 않는다.
>
> 이것은 성능 문제가 아니라 **작업 종류가 다른 것**이다. 벤치마크에 올릴 이유가 없다.

### 통과한 항목 (참고)

| K | 근거 |
| :--: | --- |
| **K1** ✅ | Service Specific Terms의 Training Restriction — *"Google won't use customer data to train or fine-tune any AI/ML models without prior permission"* |
| **K4** ✅ | Cloud Data Processing Addendum |
| **K5** ✅ | **최대 3시간 · 50GB** — 40분·4GB에 여유 |
| **K3** 🟡 | Long Running Operation **폴링** 방식. 네이티브 webhook 없음 → Pub/Sub 경유 필요 |

## 2. AWS Rekognition Video — 🟡 조건부 통과

### 재식별을 **두 API 조합**으로 푼다

| 단계 | API | 역할 |
| --- | --- | --- |
| ① 대상 지정 | `IndexFaces` | 사용자 얼굴을 **face collection에 벡터로** 저장 |
| ② 신원 탐지 | `StartFaceSearch` | 영상에서 그 벡터와 일치하는 **시각(time)** 반환 |
| ③ 궤적 | `StartPersonTracking` | 영상 내 인물별 **bbox 경로** 반환 |

**REQ-FUNC-002의 "1회 지정"이 ①에 대응한다.** GCVI에 없던 부분이 여기 있다.

### 🔴 K1 — 기본값이 학습 사용이다

> AWS는 입력을 *"solely to provide and maintain the service and, **unless you opt out as provided below**, to improve and develop the quality of Amazon Rekognition and other Amazon machine-learning/artificial-intelligence technologies"* 에 사용한다.
> 옵트아웃은 **AWS Organizations opt-out policy**로 한다.

**이것이 파일럿 동의서와 직접 충돌한다.** 클럽·학부모에게 *"학습 데이터로 쓰지 않습니다"* 라고 약속했는데, **옵트아웃 정책을 설정하지 않으면 그 약속이 자동으로 깨진다.**

| 조치 | 상태 |
| --- | :--: |
| AWS Organizations 옵트아웃 정책 적용 | 🔴 **필수 선행 조건** |
| 적용 여부를 배포 게이트에서 검증 | 🔺 **`gates/` 항목 신설 제안** — §5-2 |

> **이것은 "설정하면 되는 일"이 아니라 "설정을 잊으면 약속이 깨지는 일"이다.** 사람의 기억이 아니라 **게이트로 강제**해야 한다.

### 🔴 얼굴 벡터가 새 부담을 만든다

face collection은 **생체정보**다. 한국 개인정보보호법상 **민감정보**에 해당하며, REQ-NF-010(얼굴 정보 동의·보관·파기·위탁 4종)의 무게가 크게 늘어난다.

**파일럿 대상이 미성년자라는 점과 겹친다** — REQ-NF-017(영상 내 미성년자)과 결합하면 **법정대리인 동의 + 민감정보 처리 동의**가 동시에 필요해질 수 있다.

🔺 **법무 검토 항목으로 올린다**(§5-1).

### 통과한 항목

| K | 근거 |
| :--: | --- |
| **K2** ✅ | `StartPersonTracking`이 bbox 반환 · 영상 내 인물 식별자 유지 |
| **K3** ✅ | 비동기 Job + **SNS 완료 통지** → HTTP 엔드포인트 연결 가능 ⚠️ 세부는 착수 시 확인 |
| **K5** ✅ | **최대 6시간 · 10GB**(S3 경유) — 40분·4GB 수용 |

## 3. Replicate + SAM 2 — 🟡 조건부 통과

### 🟢 상호작용 모델이 요구사항과 정확히 일치한다

SAM 2는 **첫 프레임에 클릭한 지점의 대상을 이후 프레임으로 전파**한다.

```
click_coordinates : '[x,y]'   ← 사용자가 자기를 1회 지정
click_frames      : 0
click_object_ids  : 'me'
  ↓
이후 프레임 전체로 마스크 전파
```

**REQ-FUNC-002의 *"자기를 1회 지정"* 이 문자 그대로 이 모델의 입력이다.** 별도 설계 없이 대응된다.

### 🟢 얼굴을 쓰지 않는다 — 가장 큰 이점

클릭 좌표와 외형 기반이라 **얼굴 벡터를 생성·저장하지 않는다.** REQ-NF-010의 적용 범위가 **AWS 대비 현저히 좁아진다.**

> **DS v1.0 §4.2의 설계 결정 DD-5**(얼굴 특징 벡터 미저장)와 정합한다. 그 결정이 여기서 실현된다.

### 🟢 K1·K4 — 보존 정책이 가장 강하다

> API 예측의 *"all input parameters, output values, output files, and logs are **automatically removed after an hour**, by default."*

**1시간 후 자동 삭제**는 조사한 셋 중 가장 짧다. 학습 관련 조항은 **파인튜닝용 업로드 데이터**를 가리키며 추론 입력과 구분된다.

🔺 다만 *"추론 입력을 학습에 쓰지 않는다"* 는 **명시 문구를 문서에서 확인하지 못했다.** 계약·지원 문의로 확정해야 한다(§5-3).

### 🔴 K5 — 40분이 최대 미지수

| 항목 | 확인 결과 |
| --- | --- |
| 영상 길이 상한 | 🔴 **문서에 명시 없음** |
| 표시 실행 시간 | 약 44초 · *"predict time varies significantly based on the inputs"* |
| 표시 단가 | 약 **$0.043/run** (L40S) |

**SAM 2는 짧은 클립을 전제로 설계된 모델이다.** 40분·30fps면 약 **72,000 프레임**이고, 메모리와 시간이 길이에 따라 증가한다.

> 🔴 **표시된 $0.043은 짧은 입력 기준이며 40분의 원가가 아니다.** 이 값을 REQ-NF-013 산정에 그대로 쓰면 안 된다.
>
> **분할 처리**(구간을 나눠 호출)로 우회할 수 있으나, **구간 경계에서 동일성이 끊긴다** — 재식별이 목적인데 그것을 깨는 우회다. SP-2(Gemini 보조 경로)로 **구간을 먼저 좁히면** 이 문제가 완화된다.

### 🟡 K2 — 마스크는 나오나 bbox는 파생해야 한다

출력이 **마스크(masklet)** 다. bbox는 마스크의 외접 사각형으로 **파생 가능**하나 후처리가 필요하다.

> **정보량은 오히려 많다** — 마스크가 있으면 구도 보정(REQ-FUNC-006)에서 인물 외곽을 정확히 쓸 수 있다. K2를 *"bbox 또는 그로부터 파생 가능한 출력"* 으로 완화할 것을 제안한다(§5-4).

### 🔺 신뢰도 값 — 확인 실패

**REQ-FUNC-027(저신뢰 후보 제외)에는 구간별 신뢰도가 필요한데, Replicate 모델 페이지에서 확인하지 못했다.** SAM 2는 내부적으로 가림 예측 점수를 갖지만 **API가 노출하는지는 미확인**이다.

이것이 확인되지 않으면 **B3(신뢰도 값 제공)가 실패**하고 REQ-FUNC-027의 제외 로직이 성립하지 않는다.

## 6. 벤치마크 대상 확정

**SP-1 벤치마크는 2개 후보로 진행한다.**

| 후보 | 최우선 확인 |
| --- | --- |
| **AWS Rekognition** (PersonTracking + FaceSearch) | B1 탐지율 · B2 오인식률 · **생체정보 부담의 실제 크기** |
| **Replicate + SAM 2** | 🔴 **40분 처리 가능 여부·원가** · **신뢰도 노출** · B1 탐지율 |

**GCVI는 제외한다.** 다만 **SP-2(Gemini 보조 경로)의 비교군으로는 유용**하다 — 사람이 있는 구간을 값싸게 좁히는 용도라면 신원 없이도 쓸 수 있다.

> ### 이 조사가 SP-1에 남기는 것
>
> **벤치마크 항목이 하나 늘어야 한다.** 원래 B1~B6은 성능·원가뿐이었으나, 두 후보가 **서로 다른 법적 부담**을 남기므로 —
>
> **B7 · 규제 부담** — 채택 시 REQ-NF-010·016·017의 산출물이 몇 종 늘어나는가, 파일럿 동의서를 다시 받아야 하는가.
>
> 성능이 좋아도 **파일럿을 다시 시작해야 한다면 그것이 더 비싸다.**
