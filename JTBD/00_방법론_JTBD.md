# JTBD (Jobs To Be Done) 인터뷰 — 분석 방법론

| 항목 | 내용 |
| --- | --- |
| **문서 성격** | 방법론 · 인터뷰 수행 행동 방침 (AI 주입용 포함) |
| **적용 대상** | 하일릿(HILit) — **출시 전 · 데모 체험형** 변형 적용 |

## 0. JTBD가 다른 인터뷰와 다른 점

> **"어떤 기능을 원하세요?"가 아니라 "무엇을 하려다 그렇게 됐나요?"를 묻는다.**

사람은 제품을 사는 것이 아니라 **어떤 일을 해내기 위해 제품을 고용(hire)** 합니다. JTBD 인터뷰의 목표는 기능 요구를 수집하는 것이 아니라, **전환이 일어난 순간의 인과**를 재구성하는 것입니다.

| | 일반 사용자 인터뷰 | JTBD 인터뷰 |
| --- | --- | --- |
| 묻는 것 | 선호·만족도·기능 요구 | **전환 사건(switch event)의 전후 맥락** |
| 시제 | 현재·미래 ("어떠세요", "쓰시겠어요") | **과거** ("그때 무슨 일이 있었나요") |
| 답의 성격 | 의견 | **행동의 기록** |
| 위험 | 사용자가 만들어낸 답 | 인터뷰어가 유도한 답 |

## 1. 인터뷰 준비 및 구조

### 1-1. 시간 배정

**60~90분**을 배정합니다. 클래식한 생성 연구(generative research) 세션과 유사하며, 이 기법에 익숙하지 않은 참가자는 **편안함을 느끼는 데만 시간이 걸립니다.**

> 짧게 잡으면 표면적 답변에서 끝납니다. 심층 목표는 대개 40분 이후에 나옵니다.

### 1-2. 고유한 참가자 모집 (Recruiting)

JTBD의 핵심은 **전환 행동(switching behavior)** 을 이해하는 것이므로, 다음 세 그룹을 스크리닝하여 모집합니다.

| 그룹 | 원 정의 | 무엇을 얻나 |
| --- | --- | --- |
| **① 최근 시작** | 최근에 우리 제품/서비스를 **사용하기 시작한** 사람 | 무엇이 그들을 오게 했나 (Pull) |
| **② 최근 중단** | 최근에 우리 제품/서비스 **사용을 중단한** 사람 | 무엇이 그들을 떠나게 했나 |
| **③ 미인지** | 우리 제품/서비스에 대해 **아직 들어본 적 없는** 사람 | 진입 장벽과 대안 |

이들을 통해 사람들이 **우리 제품으로 전환하거나 떠나는 이유**, 그리고 **경쟁 제품으로 이끄는 푸시/풀(Pushes/Pulls) 요소**를 이해합니다.

### 1-3. 🔴 하일릿의 조정 — 출시 전이라 ①②가 존재하지 않는다

> **하일릿은 아직 출시되지 않았습니다.** "우리 제품을 쓰기 시작한 사람"도 "그만둔 사람"도 없습니다. 원 정의를 그대로 적용하면 모집이 불가능합니다.

**대상을 "우리 제품"이 아니라 "이 일을 해내려는 시도"로 치환합니다.**

| 그룹 | 하일릿 치환 정의 | 해당 페르소나 |
| --- | --- | --- |
| **①** | 최근 **유사 해결책을 쓰기 시작한** 사람 — 편집 앱 · 농구 스탯 앱 · 부계정 개설 | **C1** 이준호 · **C3** 한지우 · **C4** 오세라 |
| **②** | 최근 **시도했다가 그만둔** 사람 — 편집 앱을 깔았다 지운 · 촬영을 포기한 | **C2** 김태윤 · **E2** 강민석 |
| **③** | 이런 도구를 **찾아본 적 없는** 사람 | **N1** 조현아 · **N2** 윤재석 · **A2** 문혜정 |

> **②가 가장 값비쌉니다.** 시작한 사람은 왜 왔는지를 말하지만, **그만둔 사람은 무엇이 부족했는지를 말합니다.** C2는 편집 앱을 두 번 깔았다 두 번 다 지운 사람이라 이 그룹의 정확한 표본입니다.

## 2. 심층 목표 파헤치기 (Focus on Deeper Goals)

### 2-1. 표면적 답변 피하기

> **단순히 왜 다른 제품으로 전환했는지 직설적으로 묻는 것을 피합니다.**

직설적으로 물으면 참가자는 **사후에 재구성한 이유**를 말합니다. "편해서요", "괜찮아 보여서요" 같은 답은 행동을 유도한 더 깊은 목표에 도달하지 못합니다.

### 2-2. '전환 사건'에 집중

인터뷰이가 **대화의 방향을 이끌도록 허용하되**, 연구자는 참가자가 변화를 일으키게 된 **'전환 사건(switch event)'** 에 초점을 유지합니다.

> 참가자가 다른 이야기로 흘러가도 끊지 않습니다. 다만 연구자는 머릿속에서 계속 묻습니다 — *"그래서 그날, 무엇이 달랐길래 움직였나?"*

### 2-3. 스토리텔링 유도

깊은 목표와 행동을 이해하려면 **사용자가 무언가를 하기로 결정한 배경에 대한 이야기를 하도록** 유도해야 합니다. 생성 연구와 마찬가지로 심층적으로 파고들되, **특정 방식**으로 진행합니다 — 의견이 아니라 **장면을 묘사하게** 합니다.

## 3. 핵심 질문 전략 (Interview Scripting)

### 3-1. 대안 및 맥락 파악 질문

> 대화의 맥락을 잡는 단계. **경쟁자와 대체재를 참가자의 입에서 나오게** 합니다.

- 제품/서비스를 시도하기 전에 **다른 어떤 해결책을 고려**했습니까?
- 이러한 해결책을 고려할 때 **무엇을 찾고 있었습니까?**
- **무엇을 해결하려고** 했습니까?
- 이 제품/서비스들을 **어떻게 찾아보았는지** 이야기해 주십시오.
- **실제로 사용해 본** 다른 해결책은 무엇입니까?
- 시도하거나 사용해 본 다른 해결책 중에서 **좋았던 점과 싫었던 점**은 무엇입니까?
- 이 제품/서비스를 **사용할 수 없었다면 대신 무엇을** 했을 것입니까?
- **주변 사람들**이 시도하거나 사용해 본 해결책은 무엇입니까?
- **과거와 비교했을 때 지금** 무엇을 하고 있습니까?

### 3-2. 맥락 및 감정적 질문

> 경쟁사 및 잠재적 전환 행동을 파악한 **후에** 감정으로 파고듭니다. 순서를 지킵니다.

- 문제를 해결할 무언가가 필요하다는 것을 **언제 처음 깨달았습니까?**
- 고려 중인 선택에 대해 **다른 사람과 이야기**했습니까? 대화는 어땠습니까?
- 이 제품/서비스를 사용하면 **어떤 모습일지 상상**했습니까?
- 제품/서비스로부터 **무엇을 원했습니까?**
- 이것을 구매/사용하는 것에 대해 **불안감(anxiety)** 이 있었습니까?
- 사용하는 것에 대해 **걱정하게 만드는 요소**가 있었습니까?

### 3-3. 스토리텔링을 위한 연상 유도

> 사용자의 기억은 **사람·장소·냄새·소리와의 연상**을 통해 회상되는 경우가 많습니다. 기억이 막히면 사실을 캐지 말고 **장면을 복원**시킵니다.

- 그때는 **하루 중 몇 시**였습니까?
- **집에 있었습니까, 직장에 있었습니까?**
- 뒤에서 **TV가 켜져** 있었습니까?
- **당신은 어떤 상태**였습니까?

## 4. 경청해야 할 4가지 전환 동인 (Listening for the Switch)

인터뷰 내내 전환을 유도한 동기와 페인 포인트에 귀 기울입니다. **네 가지가 모두 모여야 전환이 일어납니다.**

| # | 동인 | 무엇을 듣나 | 하일릿 예시 |
| --- | --- | --- | --- |
| **1** | **상황의 푸시 (Push)** | 특정 상황 중 무엇이 그들을 새로운 해결책을 찾도록 이끌었는가 | *"3주째 못 올리니까 계정이 죽은 것 같았다"* |
| **2** | **새로운 해결책의 풀 (Pull)** | 새 해결책의 어떤 점이 시도하고 싶게 만들었는가 | *"멀리 있는 나를 알아서 따라간다는 게"* |
| **3** | **발목을 잡는 습관 (Habits)** | 시도를 방해할 수 있는 기존 습관은 무엇인가 | *"어차피 인스타에 올릴 건데 굳이"* |
| **4** | **새 해결책에 대한 불안감 (Anxieties)** | 시도·사용에 어떤 불안을 느꼈는가 | *"내 영상이 서버로 가는 건가"* |

```
    Push (현 상황의 밀어냄)  ──▶  ◀──  Habits (기존 습관의 붙잡음)
    Pull (새 해결책의 끌어당김) ──▶  ◀──  Anxieties (새것에 대한 불안)

                    전환은 앞의 둘 > 뒤의 둘 일 때만 일어난다
```

> **1·2만 듣고 끝내면 안 됩니다.** 대부분의 실패는 Push와 Pull이 충분한데도 **Habits와 Anxieties가 더 컸기 때문**에 일어납니다. 하일릿에서는 N1의 불안(초상권)과 C2의 습관(무행동)이 여기에 해당합니다.

## 5. 🔵 데모 체험형 인터뷰의 특수 설계

> **이번 인터뷰의 설정** — 참가자는 **고객용 데모 페이지를 먼저 체험**하고, 그 체험을 토대로 **자신의 기존 경험을 응답**합니다.

### 5-1. 왜 이 방식을 쓰는가

| 이유 | 설명 |
| --- | --- |
| **기억 촉발** | 데모가 3-3절의 "연상 유도"를 대신합니다. 추상적으로 묻는 것보다 **실제 화면을 본 뒤 회상이 훨씬 구체적**입니다 |
| **비교 기준 제공** | 참가자가 "지금 방식"과 "이 방식"을 나란히 놓고 말할 수 있습니다 |
| **출시 전 대응** | 하일릿은 아직 없으므로, 데모가 **가상의 전환 사건**을 만들어 줍니다 |

### 5-2. 🔴 그래서 생기는 위험 — 데모가 답을 유도한다

> **데모를 본 참가자는 이미 "정답"을 알게 됩니다.** 아무 대책 없이 진행하면 인터뷰가 **"이거 좋네요" 수집**으로 끝납니다.

| 위험 | 나타나는 모습 | 방어 |
| --- | --- | --- |
| **호감 편향** | 만들어준 사람 앞에서 좋게 말한다 | 진행자가 **제작자가 아님**을 명시. *"저는 만든 사람이 아니라 이야기를 듣는 사람입니다"* |
| **정답 유추** | "이런 걸 원했겠죠?"에 맞춰 과거를 각색한다 | **과거 회상 구간에서 데모를 언급 금지** (5-3절 Part 2) |
| **미래 의향 과대** | "쓰실 건가요?" → "네" (실제 행동과 무관) | 🚫 **"쓰시겠어요?"를 묻지 않는다.** 대신 과거에 무엇을 했는지 |
| **기능 요구 수집** | 인터뷰가 기능 위시리스트가 된다 | 기능 언급이 나오면 **"그게 없어서 곤란했던 때"** 로 되돌린다 |

### 5-3. 세션 진행 순서 (90분)

**순서가 방어 장치입니다.** 데모 → 즉시 반응 → **과거로 완전히 돌아가기** → 전환 동인 → 다시 대조.

| 구간 | 시간 | 목적 | 데모 언급 |
| --- | --- | --- | --- |
| **Part 0 · 라포·배경** | 0~10분 | 긴장 해제, 활동 맥락 파악 | 없음 |
| **Part 1 · 데모 체험** | 10~25분 | **관찰**. 말 시키지 않고 행동만 기록 | 체험 중 |
| **Part 2 · 체험 직후 반응** | 25~35분 | 첫인상·막힌 지점 | 있음 |
| **Part 3 · 🔴 과거 경험 회상** | 35~65분 | **JTBD 본체.** 대안·맥락·전환 사건 | **🚫 금지** |
| **Part 4 · 감정과 불안** | 65~78분 | Anxieties·Habits | 최소 |
| **Part 5 · 대조와 마무리** | 78~90분 | 과거와 데모를 나란히 | 있음 |

> **Part 3에서 데모를 언급하지 않는 것이 이 설계의 핵심입니다.** 진행자가 *"아까 보신 것처럼…"* 이라고 한 순간, 그 뒤의 모든 답은 데모에 오염됩니다.
> Part 2에서 Part 3로 넘어갈 때 **명시적으로 전환을 선언**합니다 — *"이제 방금 보신 건 잠깐 잊고, 지난 몇 달 이야기를 들려주세요."*

### 5-4. Part 1(체험) 중 관찰 기록표

말로 묻지 않고 **행동만 적습니다.**

| 관찰 항목 | 기록 |
| --- | --- |
| 어디서 **멈칫**했는가 (3초 이상 정지) | |
| 어디서 **되돌아갔는가** | |
| 어디서 **소리 내어 말했는가** (감탄·한숨) | |
| **손대지 않은** 기능은 무엇인가 | |
| 총 소요 시간 / 완주 여부 | |

> 멈칫한 지점은 Part 2에서 반드시 되짚습니다 — *"여기서 잠깐 멈추셨는데, 그때 무슨 생각 하셨어요?"*

## 6. 기록과 분석

### 6-1. 인터뷰 중 기록 원칙

| 원칙 | 이유 |
| --- | --- |
| **말한 그대로 적는다** | 요약하면 JTBD의 재료인 **어휘**가 사라진다. 참가자가 쓴 단어가 곧 그 사람의 세계관이다 |
| **시점을 함께 적는다** | "작년 여름", "지난달" — 전환 사건의 시간축을 복원해야 인과가 보인다 |
| **숫자를 놓치지 않는다** | "3주에 한 번", "40분", "두 번 지웠다" — 강도를 재는 유일한 재료 |
| **침묵을 적는다** | 답이 늦게 나온 질문은 대개 **처음 생각해본 것**이다 |

### 6-2. 인터뷰 후 정리 형식

```markdown
## [참가자 코드] 세션 요약

**전환 사건** — 언제, 무슨 일이 있었나 (한 문단)

| 동인 | 발언 인용 |
| --- | --- |
| Push | "…" |
| Pull | "…" |
| Habits | "…" |
| Anxieties | "…" |

**Job Statement**
"[상황]일 때, 나는 [동기]하고 싶다, 그래서 [기대 결과]할 수 있게."

**검증된 가설 / 반증된 가설**
**새로 발견한 것**
```

### 6-3. Job Statement 작성 규칙

```
When [상황], I want to [동기], so I can [기대 결과].
```

| ❌ 나쁨 | ⭕ 좋음 |
| --- | --- |
| "편하게 편집하고 싶다" | "**경기가 끝나 지하철을 탔을 때**, 오늘의 하이라이트를 5분 안에 뽑고 싶다, **그래야 계정이 살아 있고 그날이 공백으로 남지 않으니까**" |

> **기능이 들어가면 실패입니다.** "트래킹 기능으로"가 들어가는 순간 그것은 Job이 아니라 Solution입니다.

# ⚠️ 반드시 지킬 것

> # JTBD 인터뷰를 망치는 **단 하나의 질문**

**🚫 "이거 쓰시겠어요?"**

이 질문을 하는 순간, 그 세션은 JTBD가 아니라 **의향 조사**가 됩니다. 그리고 의향은 행동을 예측하지 못합니다.

### 특히 이번 인터뷰에서 위험한 이유

참가자는 **데모를 막 체험한 직후**입니다. 이 상태에서 미래 의향을 물으면 거의 모두 긍정합니다 — 눈앞에서 본 것이 좋아 보였고, 만든 사람에게 미안하고, 아직 돈을 낸 적이 없기 때문입니다.

| 🚫 묻지 말 것 | ⭕ 대신 물을 것 |
| --- | --- |
| "이거 쓰시겠어요?" | "지금까지는 그럴 때 **어떻게 하셨어요?**" |
| "얼마면 쓰시겠어요?" | "그 문제 때문에 **돈이나 시간을 쓴 적**이 있나요?" |
| "이 기능 있으면 좋겠죠?" | "그게 **없어서 곤란했던 때**를 이야기해 주세요" |
| "왜 다른 걸로 바꾸셨어요?" | "**바꾸기 전 마지막 며칠**에 무슨 일이 있었나요?" |

### 세 가지를 더 기억합니다

| # | 원칙 |
| --- | --- |
| **01** | **과거만 묻는다.** 미래 의향은 데이터가 아니다 |
| **02** | **Part 3에서 데모를 입에 올리지 않는다.** 한 번의 언급이 그 뒤 30분을 오염시킨다 |
| **03** | **Habits와 Anxieties를 끝까지 듣는다.** Push와 Pull만 들으면 전환하지 않을 사람도 전환할 것처럼 보인다 |

> **인터뷰가 끝났을 때 손에 남아야 하는 것은 "좋다는 반응"이 아니라 "그 사람이 지난 몇 달 실제로 한 행동의 기록"입니다.**
