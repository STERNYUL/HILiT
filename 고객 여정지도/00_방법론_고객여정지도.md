# 고객 여정지도 (Customer Journey Map, CJM) — 작성 방법론

| 항목 | 내용 |
| --- | --- |
| **문서 성격** | 방법론 · 재사용 기준 문서 (AI 주입용 포함) |
| **적용 대상** | 모든 서비스 — 단, **단계 정의는 서비스마다 새로 한다**(⚠️ 맨 뒤 경고 참조) |
| **참조** | [IBM · 고객 여정 지도란?](https://www.ibm.com/kr-ko/think/topics/customer-journey-map) |
| **작성** | 2026-08-28 |

---

## 1. 정의

> **고객이 "문제를 인식 → 해결을 탐색 → 구매/사용 → 평가/유지"와 같은 과정에서 겪는 경험·감정·Pain Point를 시각화한 흐름도.**

핵심은 **"우리가 무엇을 제공하는가"가 아니라 "고객이 무엇을 겪는가"** 를 시간순으로 늘어놓는 것입니다. 서비스 기능 목록이 아니라 **사람의 시간**이 축입니다.

---

## 2. 왜 만드는가

| 목적 | 설명 |
| --- | --- |
| **이탈 지점 특정** | "어딘가에서 이탈한다"가 아니라 **"몇 번째 단계, 어떤 행동에서"** 로 좁힌다 |
| **감정의 골 발견** | 기능은 다 있는데 안 쓰이는 이유는 대개 특정 순간의 감정에 있다 |
| **팀 정렬** | 기획·개발·디자인이 같은 화면을 보고 "여기가 문제"라고 합의한다 |
| **우선순위 근거** | 개선 기회에 순서를 매길 때 "여정에서 가장 깊은 골"이 근거가 된다 |

---

## 3. 구성 요소 — 세로축(레인)과 가로축(단계)

### 3-1. 가로축 = 단계 (Stage)

고객의 시간 흐름. **서비스마다 다르게 정의합니다.** (⚠️ 경고 참조)

### 3-2. 세로축 = 레인 (Lane)

각 단계에서 무엇을 기록할지. **최소 5개 레인**을 권장합니다.

| 레인 | 무엇을 적나 | 서술 형태 |
| --- | --- | --- |
| **고객 행동** | 실제로 하는 동작 | 동사 중심. 관찰 가능한 것만 |
| **고객 생각** | 머릿속 판단·질문 | **1인칭 인용구**. "이거 왜 이렇지?" |
| **감정** | 그 순간의 정서 + 강도 | 한 단어 + 강도(−3~+3) |
| **Pain Point** | 무엇이 막히는가 | 아래 5절 규칙 준수 |
| **개선 기회** | 우리가 할 수 있는 것 | 기능이 아니라 **해결 방향** |

**선택 레인** — 필요할 때만 추가합니다.

| 레인 | 언제 쓰나 |
| --- | --- |
| 접점(Touchpoint) | 채널이 여러 개일 때 (앱·웹·오프라인·고객센터) |
| 소요 시간 | 시간이 곧 이탈 요인일 때 |
| 대체 솔루션 | 지금 그 일을 어떻게 해결하고 있는지가 중요할 때 |
| 담당 조직 | 조직 간 핸드오프에서 문제가 생길 때 |
| 이탈률 | 실측 데이터가 있을 때 |

---

## 4. 단계를 정의하는 방법

### 4-1. 출발점 — 일반 5단계

가장 널리 쓰이는 기본형입니다. **출발점이지 정답이 아닙니다.**

| 단계 | 고객 행동 | 고객 생각 | 감정 | Pain Point | 개선 기회 |
| --- | --- | --- | --- | --- | --- |
| **문제 인식** | 불편함을 느낌 | "이 문제 왜 생기는 거지?" | 불안 | 정보 부족 | 문제 원인 콘텐츠 제공 |
| **탐색** | 대안을 찾음 | "이건 괜찮아 보이는데?" | 기대 | 복잡한 비교 | 비교 툴 제공 |
| **의사결정** | 선택 고민 | "이걸 사도 될까?" | 불안 | 신뢰 부족 | 후기·데모 제공 |
| **사용** | 실제 사용 | "생각보다 어렵네" | 실망 | UX 미흡 | 온보딩 개선 |
| **유지** | 반복 사용 | "이제 익숙해졌네" | 안정 | 가치 감소 | 리텐션 캠페인 |

> 마케팅 문헌에서는 여기에 **옹호(Advocacy)** 를 더해 `인지 → 고려 → 결정 → 유지 → 옹호` 5단계로 쓰기도 합니다.

### 4-2. 우리 서비스의 단계를 찾는 4가지 질문

기본형을 그대로 쓰지 않고 **우리 서비스 고유의 단계**를 뽑아내는 절차입니다.

| # | 질문 | 무엇이 나오나 |
| --- | --- | --- |
| **Q1** | 고객이 **시간을 가장 많이 쓰는** 구간은 어디인가? | 그 구간은 반드시 **쪼개야** 한다 |
| **Q2** | 고객이 **가장 자주 포기하는** 지점은 어디인가? | 그 앞뒤가 별도 단계가 된다 |
| **Q3** | 이 업종에만 있는 **고유 행위**는 무엇인가? | 이것이 그 시장의 시그니처 단계다 |
| **Q4** | **구매 이후에도** 여정이 계속되는가? | 계속된다면 사용·유지를 세분화한다 |

### 4-3. Q3의 실제 사례 — 업종마다 단계가 완전히 다르다

| 시장 | 그 시장에만 있는 고유 단계 | 왜 생기나 |
| --- | --- | --- |
| **가구** | **실측** · **조립/설치** | 물리적 공간에 들어가야 하고, 구매 후에도 노동이 남는다 |
| **자동차** | **비교** · **시승** · **협상** | 고관여·고가라 검증 절차가 길고, 가격이 고정되어 있지 않다 |
| **SaaS** | 무료 체험 · 팀 초대 · 결제 승인 | 사용자와 결제자가 다르다 |
| **의료** | 증상 검색 · 예약 · 대기 · 진료 후 관리 | 불안이 여정 전체를 지배한다 |

> **가구 시장의 CJM에 "시승"이 없고, 자동차 시장의 CJM에 "조립/설치"가 없습니다.** 같은 템플릿을 두 시장에 쓰면 둘 다 틀립니다.

## 5. Pain Point 서술 규칙 ★

CJM의 값어치는 대부분 이 레인에서 나옵니다. **모호한 Pain Point는 개선 기회를 도출할 수 없습니다.**

### 5-1. 반드시 지킬 3가지

| # | 규칙 | 설명 |
| --- | --- | --- |
| **01** | **관찰 가능하게** | 추측한 심리가 아니라 **행동으로 드러나는 것**을 적는다 |
| **02** | **한 문장, 하나의 막힘** | 두 가지가 섞이면 개선 기회도 두 개로 갈라져 우선순위를 못 매긴다 |
| **03** | **왜 막히는지까지** | 현상만 적으면 대응이 증상 치료로 끝난다 |

### 5-2. 나쁜 서술 vs 좋은 서술

| ❌ 나쁨 | 왜 나쁜가 | ⭕ 좋음 |
| --- | --- | --- |
| "불편함" | 무엇이 불편한지 없음 | "40분 원본에서 좋은 장면만 고르는 데 30분이 더 든다" |
| "UX가 미흡함" | 평가일 뿐 사실이 아님 | "편집 앱을 열면 첫 화면이 타임라인이라, 무엇부터 눌러야 할지 알 수 없다" |
| "가격 부담" | 누구에게 얼마가 부담인지 없음 | "월 회비 3만 원인 동호회에서 연 190만 원은 예산의 26%다" |
| "신뢰 부족" | 무엇을 못 믿는지 없음 | "영상이 서버로 가는지 기기 안에서 처리되는지 화면 어디에도 없다" |

### 5-3. 서술 템플릿

```
[언제·어디서] + [무엇을 하려다] + [무엇 때문에 막히는가]
```

> 예 — *"경기 직후 지하철에서(언제) 후보 30개를 훑으려다(무엇을) 한 손 조작이라 스크롤이 안 되어(왜) 그날 발행을 포기한다."*

## 6. 작성 원칙

> ### *"예쁘면 다 좋은 게 아니라, 지식으로서 가치있는 부분을 가독성 높고 재사용하기 쉽게 추출하기"*

| 원칙 | 지키는 방법 |
| --- | --- |
| **재사용 가능하게** | 표 구조를 유지한다. 그림으로만 그리면 다음 사람이 수정할 수 없다 |
| **인용 가능하게** | 고객 생각은 **큰따옴표 1인칭**으로. 그대로 회의에서 읽을 수 있어야 한다 |
| **비교 가능하게** | 여러 페르소나를 그릴 때 **레인 이름과 감정 척도를 통일**한다 |
| **검증 가능하게** | 가설과 실측을 구분 표기한다 (⚠️ 미검증 / 🔍 인터뷰 확인) |
| **장식하지 않는다** | 아이콘·색은 정보를 나를 때만. 예쁘게 만들려고 넣지 않는다 |

## 7. 작성 절차 6단계

| # | 단계 | 산출 |
| --- | --- | --- |
| **1** | **대상 페르소나 확정** | 한 장에 한 명. 여러 명을 섞으면 어느 단계도 사실이 아니게 된다 |
| **2** | **여정의 시작과 끝을 정한다** | "서비스를 켜기 전"부터 시작할지, "구매 후 3개월"까지 갈지 |
| **3** | **4-2의 4가지 질문으로 단계를 뽑는다** | 이 서비스 고유의 단계 목록 |
| **4** | **레인을 채운다** | 행동 → 생각 → 감정 → Pain Point → 개선 기회 순서로 |
| **5** | **감정 곡선을 그린다** | 가장 깊은 골이 최우선 개선 지점 |
| **6** | **가설과 사실을 표시한다** | 인터뷰로 확인해야 할 칸을 남긴다 |

> **4번의 순서를 지킵니다.** 개선 기회부터 적으면 이미 만들고 싶은 기능에 맞춰 Pain Point를 역산하게 됩니다.

## 8. 좋은 CJM / 나쁜 CJM

| | 나쁜 CJM | 좋은 CJM |
| --- | --- | --- |
| 단계 | 어느 서비스에나 붙는 일반 5단계 | 이 서비스에서만 나오는 단계가 섞여 있다 |
| 감정 | 전 구간이 "보통" | 골과 봉우리가 뚜렷하다 |
| Pain Point | "불편함", "복잡함" | 언제·무엇을·왜가 한 문장에 있다 |
| 개선 기회 | 이미 만들기로 한 기능 목록 | Pain Point에서 역산된 방향 |
| 검증 | 전부 확정처럼 보인다 | 가설과 확인된 것이 구분되어 있다 |
| 재사용 | 이미지 한 장 | 표 + 인용 가능한 문장 |

# ⚠️ 반드시 읽고 시작할 것

> # 고객 여정지도의 단계는 **고정된 템플릿이 아닙니다**

**고객 여정지도라는 결과물은 균일하게 항상 같은 단계로 작성되는 것이 아닙니다. 매번 서비스의 특성에 따라 핵심 단계가 새롭게 정의되어 제작되어야 합니다.**

### 왜 이 경고가 필요한가

4-1절의 일반 5단계(`문제 인식 → 탐색 → 의사결정 → 사용 → 유지`)는 **출발점일 뿐 정답이 아닙니다.** 그런데 이 표가 문서에 있다는 이유만으로 그대로 복사해 쓰는 일이 반복됩니다. 그렇게 만든 여정지도는 **어느 서비스에 붙여도 말이 되고, 그래서 어느 서비스에도 쓸모가 없습니다.**

| 시장 | 그 시장을 설명하는 진짜 단계 |
| --- | --- |
| 가구 | **실측** · **조립/설치** ← 일반 5단계 어디에도 없다 |
| 자동차 | **비교** · **시승** · **협상** ← 마찬가지 |

### 자가 점검 — 이 질문에 "예"면 다시 만드세요

- [ ] 우리 여정지도의 단계 이름을 **다른 업종에 그대로 붙여도** 말이 되는가?
- [ ] 단계가 **정확히 5개**인가? (우연히 5개일 수는 있지만, 5개에 맞추려 한 적은 없어야 한다)
- [ ] 이 서비스를 아는 사람만 알아볼 단계 이름이 **하나도 없는가?**
- [ ] 페르소나가 여럿인데 **모두 같은 단계**를 쓰고 있는가?

> **마지막 항목이 특히 중요합니다.** 같은 서비스라도 페르소나에 따라 여정의 시작점·끝점·단계 수가 달라집니다.
> — 이미 그 일을 하고 있는 사람은 "탐색" 단계가 없습니다.
> — 서비스를 거부하는 사람은 여정이 **"인지" 이전에서 끝납니다.**
> — 조직이 구매하는 경우 **"내부 승인"** 이라는 단계가 개인에게는 없습니다.
> — 저장이 끝이 아닌 서비스는 **"몇 달 뒤 다시 열어보기"** 가 진짜 사용 시점입니다.

### 그래서 이 문서를 쓰는 순서

```
4-2절 4가지 질문으로 단계를 먼저 뽑는다
        ↓
그 결과가 우연히 일반 5단계와 같다면 → 그때 써도 된다
        ↓
다르다면 → 다른 것이 맞다. 템플릿에 맞추지 않는다
```

**템플릿에 서비스를 맞추지 말고, 서비스에서 단계를 꺼내십시오.**
