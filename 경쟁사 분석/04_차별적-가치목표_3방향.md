# 차별적 가치목표 3방향 — 근거에서 결론까지

| 항목 | 내용 |
| --- | --- |
| **입력** | 경쟁사 14곳의 가치 선언 (팀 9곳 + 보완 5곳) |
| **방법** | 각 사가 **무엇을 약속하고 무엇을 포기했는지**에서 빈자리를 찾고, **실측 데이터로 그 빈자리가 우리 것인지 검증** |
| **구조** | 🔴 **세 방향은 택일이 아니라 세 개의 독립 축.** 하나가 빠지면 나머지 둘이 무너진다 |
| **작성** | 2026-08-28 |

## 세 개의 빈자리

```
빈자리 A · 진입   하드웨어 없이 화면을 재구성하는 곳     → 14곳 중 0곳
빈자리 B · 판단   사용자가 최종 장면을 고르는 곳         → 스포츠 AI 9곳 중 0곳
빈자리 C · 보존   영상을 다루면서 축적이 목적인 곳       → 14곳 중 0곳
```

> **세 빈자리가 각각 다른 경쟁 계층에서 나옵니다** — A는 스포츠 하드웨어 5사에서, B는 스포츠 AI 9곳 전부에서, C는 SNS·편집 도구 5곳에서. **하나의 경쟁사가 셋을 동시에 막고 있지 않습니다.**

# 2. 🔵 방향 ① — 진입 축

## 가치 선언

> ### *"카메라를 사지 않고, 다음 경기를 기다리지 않는다. 지난주에 찍어둔 영상으로 오늘 시작한다."*

## 근거 사슬

```
[실측 1] 하프코트 드릴 구간 5~8m에서 인물이 화면의 28~47%
              ↓ 그래서
[가능]   1~2배 확대만으로 "화면 중앙 배치"가 성립한다
              ↓ 그래서
[대비]   Trace는 축구장 105m라 4배가 필요해 듀얼렌즈를 판다
              ↓ 결론
[선언]   우리는 하드웨어를 안 쓰는 게 아니라, 안 써도 되는 종목을 골랐다
```

| 2 | **축구장 105m vs 하프코트 14m** | FIFA·FIBA 규격 | Trace가 하드웨어를 파는 이유가 설명되지 않음 |

# 3. 🟢 방향 ② — 판단 축

## 가치 선언

> ### *"AI는 40분을 30개로 줄이는 일까지만 한다. 오늘 그 장면이 왜 특별한지는 당신만 알기 때문이다."*

## 근거 사슬

```
[실측]   스포츠 AI 9곳 전부 기계 판정 — 사용자 선택 구조 0곳
              ↓ 그런데
[관찰]   판정 기준이 "점프·슛 릴리스"면 휠체어 농구는 후보에 안 뜬다
              ↓ 그래서
[함의]   기계 판정은 기준 밖 사용자를 구조적으로 배제한다
              ↓ 그리고
[자산]   사용자 선택이 쌓이면 추천이 좋아지는 순환이 생긴다
              ↓ 결론
[선언]   고르는 일을 남기는 것이 포용성이자 방어선이다
```

## 근거 상세

| # | 근거 | 출처 | 🔴 이것이 없었다면 |
| --- | --- | --- | --- |
| 1 | **스포츠 AI 9곳 중 사용자 선택 구조 0곳** | 경쟁사 분석 ③-B | 빈자리 주장이 성립 안 함 |
| 2 | **D-3 휠체어 농구는 점프 기준에서 배제됨** | 페르소나 카드 | 기계 판정의 구조적 한계를 보일 수 없음 |

| --- | --- |

# 5. 🔴 세 방향은 왜 모두 필요한가

## 5-1. 하나를 빼면 나머지가 무너집니다

| 빠지는 것 | 무슨 일이 일어나나 |
| --- | --- |
| **① 진입** 없이 ②③만 | 하드웨어를 사야 하면 **애초에 아무도 안 들어옵니다.** 판단권도 축적도 경험할 사람이 없습니다 |
| **② 판단** 없이 ①③만 | 기계가 다 고르면 **화질 제약에서 실망합니다.** *"AI가 알아서"* 라고 해놓고 결과가 아쉬우면 신뢰가 무너집니다 |
| **③ 보존** 없이 ①② 만 | 편집 도구가 됩니다. CapCut과 같은 시장에서 **무료 강자와 정면으로 붙습니다** |

## 5-2. 셋이 서로를 지탱하는 구조

```
①  진입   "안 사도 된다"        →  사람이 들어온다
                                        ↓
②  판단   "당신이 고른다"        →  기대치가 정확해지고
                                     선택 데이터가 쌓인다
                                        ↓
③  보존   "안 올려도 남는다"      →  아카이브가 쌓여
                                     떠나지 못한다
                                        ↓
                                   그 시간에 ①의 정확도가 올라간다
```

> **②가 ①의 약점을 덮습니다.** 화질 상한이 1.125배라는 사실은 *"AI가 다 해준다"* 고 하면 실망이지만, *"AI는 좁히기만 하고 고르는 건 당신"* 이라고 하면 **정직한 기대치**가 됩니다.
>
> **③이 ①의 시간을 벌어줍니다.** 진입 우위는 Trace가 하드웨어를 버리면 사라지지만, 그때쯤 쌓인 아카이브는 옮길 수 없습니다.
>
> **①이 ③의 전제입니다.** 축적은 사용자가 들어와야 시작됩니다.

## 5-3. 각 방향이 다른 것을 검증합니다

| 방향 | 검증하는 KSF | 검증 시점 | 실패 시 신호 |
| --- | --- | --- | --- |
| **① 진입** | KSF ① 정확도 · KSF ⑤ 좁게 시작 | **첫날** | 첫 결과물에서 이탈 |
| **② 판단** | KSF ② 데이터 자산 | 수 주 | `다시 고르기` 클릭률 급증 |
| **③ 보존** | KSF ④ 축적 | 수 개월 | 저장 후 재방문 0 |

> **셋의 검증 시점이 다릅니다.** 하나만 택하면 나머지 두 KSF를 검증할 수단이 사라집니다.

# 6. 노출 순서 — 유효성이 아니라 순서의 문제

세 방향 모두 유효하지만, **사용자가 만나는 순서**는 다릅니다.

| 접점 | 어느 선언을 | 왜 |
| --- | --- | --- |
| 앱스토어·광고·첫 화면 | **① 진입** | 유일하게 **한 문장으로 전달**됨 |
| 제품 사용 중 | **② 판단** | 써봐야 알 수 있음 |
| 온보딩 · 저장 직후 | **③ 보존** | *"올리지 않아도 됩니다"* 를 그 자리에서 |
| 3개월 뒤 알림 | **③ 보존** | 축적이 실현되는 순간 |

> ⚠️ **이건 중요도 순서가 아니라 인지 순서입니다.** ③이 마지막에 오는 이유는 덜 중요해서가 아니라 **체감에 시간이 걸리기 때문**입니다.
