## 1. 축약의 판정 기준

병합 여부를 **크기가 아니라 아래 5개 질문**으로 판정했다. 하나라도 "아니오"면 병합하지 않았다.

| # | 질문 | 이유 |
| :--: | --- | --- |
| **1** | 같은 모듈·같은 파일을 만지는가? | 아니면 PR이 갈라진다 |
| **2** | 담당자와 리뷰 관점이 같은가? | 법무·디자인·개발이 섞이면 승인 체인이 꼬인다 |
| **3** | **차단자가 같은가?** | 🔴 **다르면 병합이 병렬화를 죽인다** |
| **4** | 종료 조건이 같은 종류인가? | 완료형 + 수렴형을 합치면 판정 불가 |
| **5** | **요구사항이 분리를 명시하지 않았는가?** | 🔴 **명시했다면 절대 병합 불가** |

**3번이 가장 많은 병합을 막았다.** 예: `FR-008 어댑터`(SP-1 차단)와 `FR-009 제외`(Mock으로 지금 가능)를 합치면, **Mock으로 병렬 진행하려던 설계 의도가 통째로 사라진다.**

## 5. 실행 방법 — 🔴 재번호를 하지 않는다

### 5.1 문제

이미 **본문 58건이 작성됐고**, 각 문서가 서로를 **ID로 참조**한다 (`Blocks: FR-020` · `Depends on: CT-003` …). **재번호하면 참조가 전부 끊긴다** — 팀 SRS ID를 보존했던 것과 같은 이유다.

### 5.2 해법 — 흡수 측 ID 유지

```
FR-001 (유지) ← FR-002 · FR-003 흡수
                 ↳ 폐번 · 리다이렉트 표에만 남긴다
```

**살아남는 쪽의 ID를 그대로 쓴다.** 그러면:

| | 영향 |
| --- | --- |
| 유지 태스크를 가리키는 참조 | 🟢 **전부 그대로 유효** |
| 흡수된 ID를 가리키는 참조 | 🔺 **리다이렉트 표 1개**로 해소 |

### 5.3 작업량
