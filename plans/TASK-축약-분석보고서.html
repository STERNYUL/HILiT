1. 축약의 판정 기준

병합 여부를 크기가 아니라 아래 5개 질문으로 판정했다. 하나라도 "아니오"면 병합하지 않았다.

#질문이유
1같은 모듈·같은 파일을 만지는가?아니면 PR이 갈라진다
2담당자와 리뷰 관점이 같은가?법무·디자인·개발이 섞이면 승인 체인이 꼬인다
3차단자가 같은가?🔴 다르면 병합이 병렬화를 죽인다
4종료 조건이 같은 종류인가?완료형 + 수렴형을 합치면 판정 불가
5요구사항이 분리를 명시하지 않았는가?🔴 명시했다면 절대 병합 불가

3번이 가장 많은 병합을 막았다. 예: FR-008 어댑터(SP-1 차단)와 FR-009 제외(Mock으로 지금 가능)를 합치면, Mock으로 병렬 진행하려던 설계 의도가 통째로 사라진다.

4. 🔴 절대 병합 불가 — 6쌍

아래는 크기가 작아도 합치면 요구사항이 깨진다. 축약안에서 전부 제외했다.

#대상합치면 무엇이 깨지는가
1FR-004 원본 삭제 ↔ FR-024 정보주체 삭제🔴 결과가 정반대다 — 앞은 완성 영상을 남기고(SET NULL), 뒤는 함께 지운다. 한 함수가 되면 둘 중 하나는 반드시 틀리고, 틀린 쪽이 법적 의무다

3FR-008 어댑터 ↔ FR-009 제외🔴 차단자가 다르다 — FR-008은 SP-1 대기, FR-009는 Mock으로 지금 가능. 합치면 병렬화 설계가 통째로 무효가 된다
4FR-018·019 기록 저장 ↔ FR-020 공개 범위🔴 §6.3 규칙 1 — "저장과 공개는 분리된 행위다". 요구사항 본문이 분리를 명시했다
5NF-015 ~ 018 법무 게이트 4건🔴 각각 별도의 gate.json·승인 체인·차단 대상을 갖는다. NF-015는 가입 전체를, 나머지는 공개 발행을 막는다. 합치면 하나가 미승인일 때 전부 막힌다

5. 실행 방법 — 🔴 재번호를 하지 않는다

5.1 문제

이미 본문 58건이 작성됐고, 각 문서가 서로를 ID로 참조한다 (Blocks: FR-020 · Depends on: CT-003 …). 재번호하면 참조가 전부 끊긴다 — 팀 SRS ID를 보존했던 것과 같은 이유다.

5.2 해법 — 흡수 측 ID 유지

FR-001 (유지) ← FR-002 · FR-003 흡수

영향

흡수된 ID를 가리키는 참조🔺 리다이렉트 표 1개로 해소
